Leakage checks

  • record_id stays an identifier. It is not a column of the feature matrix.
  • actual_yield_kg is the regression target only. Classification rejects it as a feature. Clustering rejects it as an input.
  • dispatch_attention is the classification target only. Clustering rejects it as an input. A value other than 0 or 1 fails the data check.
  • src/regression.py does not import scikit-learn and does not call LinearRegression. The weight update is batch gradient descent in NumPy.

Scaler checks

  • Regression and classification fit the feature mean and scale on the training rows only. The tests compare that mean with the training slice and with the full table.
  • Clustering is unsupervised, so its scaler is fit on every row that is being clustered. Those rows are still input measures only.
  • The recorded seed in each metrics builder is 42. Repeating a fit with the same seed repeats the regression weights, the classifier coefficients, and the cluster labels.

Clustering rule checked here

Scores are computed for k = 2, 3, 4, and 5. The selected k is the highest silhouette. If two scores tie, the smaller k is kept. test_tie_keeps_the_smaller_k locks that rule. Every input row in the synthetic table receives one label, and clusters.csv has one line per record id. The metrics text states that a cluster is not a verified real-world category.

The classification scores use positive class 1. The confusion matrix is ordered with labels 0 then 1. A single-class training table is rejected rather than scored.
