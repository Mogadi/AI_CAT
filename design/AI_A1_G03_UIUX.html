Stakeholder. The dispatch officer at Musanze HarvestLink Cooperative. The officer is not a modeller. The work happens at a collection desk, sometimes with strong window light, on a laptop. The next action has to be readable without interpreting a chart legend first.

Problem. Before a potato consignment leaves, the officer needs three answers from the issued batch, then a human decision. The model proposes. The officer dispatches, holds, or overrides.

  1. Expected harvest weight. An estimate in kilograms from the six farm measures. It is not a scale reading.
  2. Dispatch attention. Whether this consignment should be held for a look before it leaves.
  3. Operating profile. Which other collection rows look similar on those same measures. A profile is not a verified farm type.

What Member 1 owns. The schema check, the feature matrix, data_report.json, and this dashboard. The matrix uses plot area, rainfall, soil pH, seed, distance, and arrival hour. record_id stays a label. actual_yield_kg and dispatch_attention stay targets and are not inputs. Pages 2 to 7 are the owned design. Later members fill the numbers the screens reserve.

Page 2 · User journey and information flow

From the CSV to a human decision

Primary user. Dispatch officer on the HarvestLink desk.

Goal. Confirm the file, read the three results for a consignment, and record Dispatch, Hold, or Override.

Constraint. Figures come from the pipeline for group AI-G03. The officer cannot rename columns or type over a result. A failed file check shows no weight, warning, or profile.

1. UploadOfficer chooses the issued CSV. The header already shows AI-G03.
2. File checkFingerprint, row count, missing cells, duplicate ids.
3. ResultsExpected kg, attention word, and profile for each complete row.
4. One rowThe officer opens a consignment and reads all three together.
5. DecideDispatch, Hold, or Override with the model still visible.

Happy path

  1. Open the desk. Read AI-G03 in the header.
  2. Upload the group CSV. The screen shows the SHA-256 of those exact bytes and the file name.
  3. Read the file check. Six features are named in words. Missing cells and duplicate ids are counts, not colours alone.
  4. Open the batch. Each complete row has an expected weight, an attention word, and a profile word.
  5. Open one consignment. The six measures are listed beside the three results and the model version.
  6. Record the decision. Dispatch and Hold need one click. Override needs a written reason. The result stays on the record.

Paths the officer will actually hit

  • Wrong table. A missing or extra column stops the desk. The message names the columns. No results are drawn.
  • Empty cell. That row is listed as incomplete and has no weight, flag, or profile. Complete rows remain reviewable.
  • Repeated record id or repeated row. The count is shown on the file check. Both copies stay visible so the officer can compare them.
  • Bad attention label. A value other than 0 or 1 stops the file check and names the field.
  • Single-record form. A missing or non-numeric measure blocks prediction and names the field. The other fields stay filled.
  • Close call. When the attention score sits between 40 and 60 in 100, the chip reads Uncertain. Hold remains the filled button.

Page 5 · Responsible AI states

Uncertainty, gaps, limits, and override

These four states are part of the desk. A result screen without them is incomplete.

Uncertainty

Uncertain

When the attention score is from 40 to 60 in 100, the chip reads Uncertain even if the model leans one way. The sentence says the two outcomes are too close. Hold is the filled button. The score remains visible as a count out of 100.

Missing data

Stopped

File: “Rainfall is missing on 2 rows. Those rows have no weight, warning, or profile.” Single record: “Rainfall must be a number. Nothing was predicted.” The named field is the only one cleared of its error when the officer fixes it.

Model limitation

A standing note sits under every result. “This estimate uses six measures from the group file. It does not know the road, the sacks, or today’s queue. A profile is not a farm type.” The note stays when the numbers look confident.

Human override

Override opens a reason box: “Why are you overriding the suggestion?” Save stays unavailable until the reason has a short sentence. The stored record keeps the model weight, the attention word, the profile, the model version, AI-G03, the officer’s decision, and the reason.

Legend and status rules

  • Attention chips: Ready, Hold, Uncertain. Each has a word, a border, and a fill.
  • Profile marks: circle, square, triangle, diamond, and a cross if k is 5. The legend lists Profile plus the number. The plot and the table use the same pair.
  • One filled button per decision row. Hold is filled when the chip is Hold or Uncertain. On a Ready row, Dispatch can be the filled button, and Hold stays one click away.
  • Buttons are at least 48 by 48. Gap between two buttons is 8. Screen padding is 16. Cards use 8 px corners.
  • Error text uses Hold red and the sentence. A red border without words is not a message.

Page 7 · Three decisions

Why the desk is arranged this way

Decision 1 — The file check is a gate

The officer sees the fingerprint, the column check, the missing cells, and the duplicate counts before any weight. Review results does not open on a failed table. Justified because a later file can keep the column meanings and change the rows, and a familiar file name is not proof. Acting on a weight from the wrong table is the failure this screen is built to prevent.

Decision 2 — Hold is the filled action on a warning

When the chip says Hold or Uncertain, the filled button is Hold. Dispatch anyway is secondary. Override keeps the suggestion on the record and requires a reason. Justified because a load that leaves and later proves it needed a check is harder to recover than a load kept at the desk. The officer can still send it. The model does not send it.

Decision 3 — Profiles stay numbered

Clusters are Profile 1 upward, with a shape and a colour, plus the sentence that a profile is not a verified farm type. The desk does not invent names such as “weak farms”. Justified because the same grouping can mix different causes, k is only the silhouette choice from 2 to 5, and a category name would overclaim what the plot can show.

Accessibility checks

  • Body text stays dark on white and on warm paper. The filled button is white on slate.
  • Every status the officer acts on includes the word Ready, Hold, Uncertain, Passed, Stopped, or Incomplete.
  • The profile plot can still be read from the shape and the number when colour fades.
  • Text uses the system font and wraps. Zoom must not clip a chip or a button label.
  • The main actions are at least 48 by 48, including Hold, Dispatch anyway, Override, and Save decision.
